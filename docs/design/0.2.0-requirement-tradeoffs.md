# Requirement trade-offs

Every requirement in `docs/spec/`, with the alternative that was available and
why it lost. `0.2.0-decisions.md` argues the twenty-nine genuinely open choices
at length; this covers all 300, including the ones whose alternative is simply
"diverge from `v0.1.0`".

Stating that alternative per requirement is not filler. Parity is a constraint
we chose, and each requirement is a place we are paying for it. A row whose
reversal condition is "parity is abandoned" is telling you that the requirement
has no independent justification, and that is worth knowing before someone
defends it on its merits.

**Reading the table.** *Alternative* is what a competent person would otherwise
have written. *Why* is the reason it lost, in the terms of this project.
*Reverses if* is the observation that would make us revisit. Rows marked **D**
are argued at length in `0.2.0-decisions.md`, either as one of the architecture
decisions in its §2 or as a requirement in its §3. There are 38 of them.

## meowctl-common

| ID | Alternative | Why this one | Reverses if |
| --- | --- | --- | --- |
| R-COMMON-001 | One string type for a component | Three syntaxes with different resolution rules; a string cannot say which it holds | Never: the three forms are in every user's `init.star` |
| R-COMMON-002 | Compute the module key at each call site | `apply.go` computes it once and four callers re-derive it; each is a place to get `//` splitting wrong | The lock stops being keyed by module |
| R-COMMON-003 | Accept any string as a `ModuleRef` | A malformed ref becomes a registry lookup for a nonsense name and a confusing 404 | Never |
| R-COMMON-004 | Store integrity as a plain string | An unvalidated hash compares unequal forever and looks like tampering | SRI is replaced by another hash format |
| R-COMMON-005 | Hash where the bytes are, in the cache and in `ctx.download` | Two implementations of one hash is how a tool ends up with two encodings of it and no way to tell a mismatch from a spelling | Never |
| R-COMMON-010 | Fewer, coarser phases | Thirteen is what components already export as hook names; merging any breaks files | Hook names change, which breaks parity |
| R-COMMON-011 | Let each command list its own phases | The mapping is fixed and duplicating it is how a phase gets dropped from one command | A command needs a phase set of its own |
| R-COMMON-012 | Check the phase name at each call site | `v0.1.0` does, in `methods.go`, and the set has to agree with `ctx` and the executor | Read-only stops being a property of the phase |
| R-COMMON-013 | Treat `emit` as always-on | Emitting outside a hook phase writes into a piped run's stdout | `emit` gets its own channel |
| R-COMMON-020 **D** | Resolve exactly as `v0.1.0` | The corpus needs two binaries on one config without a flag per call | The corpus stops needing it |
| R-COMMON-021 **D** | Hard-code `~/.cache`, as `cacheDir` does | XDG is already honoured for config, and splitting the convention means a machine that relocated its cache still has meowctl writing to the default | Never |
| R-COMMON-022 **D** | Accept relative paths and `~user`, as `v0.1.0` does | A hook has no defined working directory, so a relative path resolves somewhere its author cannot predict, and `~user` becomes a directory literally named `~user` | A hook gains a defined working directory |
| R-COMMON-030 | Richer exit codes | Scripts already branch on these five; adding codes changes behaviour silently | A caller needs to distinguish a case these merge |
| R-COMMON-031 | Let crates choose codes | That is how `v0.1.0` spreads `exitErrorf` through the CLI layer; a crate that knows its exit code knows about a process | Never |
| R-COMMON-032 | Errors carry a message only | `v0.1.0` does, and a Starlark mistake reports a file and no line | Never: M0 showed the span is free |
| R-COMMON-040 | A smaller event set, extended when needed | A sink cannot show what is not emitted, and the engine is the awkward place to add one later | An event proves unused after the sinks exist |
| R-COMMON-041 | Serialize only what `JsonSink` needs | Two representations of one event drift | JSON output is dropped |
| R-COMMON-042 | Allow free text anywhere | It is how `Writer.Log` made `v0.1.0`'s output unstructurable | A case appears that genuinely has no structure and no severity |
| R-COMMON-043 | Let the engine pick a glyph | Then `JsonSink` emits terminal decoration and the engine holds a theme | Never |
| R-COMMON-050 | Panic on malformed input | These strings come from files users edit | Never |
| R-COMMON-051 | Map an unknown phase to a default | A `state.toml` from a newer build would be silently misread | Never |

## meowctl-fs

| ID | Alternative | Why this one | Reverses if |
| --- | --- | --- | --- |
| R-FS-001 | A broader trait covering everything `std::fs` offers | Each method needs three implementations and an inverse story; unused breadth is cost with no user | A component needs an operation the set omits |

| R-FS-006 | One `remove` that takes a directory too, or recursion at the call site | An undo removing one empty directory and a cache discarding a subtree are different decisions, and a single method makes the dangerous one the default | Nothing needs to discard a subtree |
| R-FS-005 | Let the module extractor `chmod` directly | A path around the trait is a path a dry run cannot intercept, and the executable bit is the one mode a caller decides | Modules stop shipping executables |

| R-FS-014 | Generics rather than a trait object | Monomorphising the engine over three filesystems for no measured gain | A measurement shows the virtual call costs something |
| R-FS-020 | Fail on an existing symlink | Re-running `apply` is the normal case and would fail every time | Never |
| R-FS-021 | Silently overwrite a regular file | A user loses a file they wrote by hand, with no record | Never |

| R-FS-033 **D** | Let a dry run succeed at everything | A dry run that succeeds where the real run fails is worse than none | False negatives become the common complaint |
