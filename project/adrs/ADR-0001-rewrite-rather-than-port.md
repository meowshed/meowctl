# 0001. Rewrite meowctl in Rust with the architecture corrected, rather than port the Go code

## Decision

`v0.2.0` is a ground-up rewrite in Rust that fixes the twelve architectural
defects of `v0.1.0`, rather than a mechanical port of the Go code (from
docs/design/0.2.0-rust-rewrite.md §1, high). Each defect maps to a crate
boundary, and the defect list is the whole licence to change design: anything
else is an issue against 0.3.0 (from docs/design/0.2.0-rust-rewrite.md §2 and
§5, high). The requirements that carry the fixes include REQ-3001 for the staged
pipeline, REQ-3051 and REQ-1622 for defect #11, REQ-3410 for effects built at
the binary, REQ-1031 for one exit-code mapping and REQ-3412 for commands built
per invocation (from docs/spec/engine.md, docs/spec/exec.md, docs/spec/cli.md
and docs/spec/common.md, high).

Defect #7, errors as formatted strings, is fixed by typed errors built with
`thiserror` and by the span rendering `starlark-rust` already provides, which
prints a traceback with a caret under the offending source (from Cargo.toml and
docs/spec/starlark.md, high). The plan named `miette` for this, and no crate
depends on it, because the library's rendering already carries the span (from
docs/design/0.2.0-rust-rewrite.md:147 and `rg -l miette Cargo.toml
crates/*/Cargo.toml`, high).

Once accepted, the Go tree is replaced and every defect has a boundary that
holds it.

## Why

The Go code's problems are architectural, and a mechanical port would carry all
of them across (from docs/design/0.2.0-rust-rewrite.md §1, high). The defects
are specific: `internal/cli` is a god-package, domain policy leaks into the CLI,
`ctx` mixes four concerns in one file, dry-run is a scattered `if`, config edits
are regex surgery, schemas are spread over five packages, errors are formatted
strings, state is package-level, the two-pass evaluation is a comment, tests
reach for the real machine, the engine holds a renderer, and output is only ever
text (from docs/design/0.2.0-rust-rewrite.md §2, high).

The rewrite also buys one deployable artifact with no runtime assumptions, types
that encode the domain, effects behind traits, and consistency with `vlie`,
which is the reference for how Rust is organised here (from
docs/design/0.2.0-rust-rewrite.md §1, high). Parity with `v0.1.0` is what makes
the rewrite verifiable, because `v0.1.0` becomes an oracle (from
docs/design/0.2.0-rust-rewrite.md §1, high).

## Alternatives

| Option | Better at | Why it lost |
| --- | --- | --- |
| Port the Go code mechanically | Less design work; the result mirrors a tree that already runs | It carries every architectural defect across (from docs/design/0.2.0-rust-rewrite.md §1, high) |

## What it costs

The rewrite ships no new user-facing features, so the whole of `v0.2.0` is spent
on the same product (from docs/design/0.2.0-rust-rewrite.md §1, high). The risk
it takes on is Starlark dialect parity between `go.starlark.net` and
`starlark-rust`, which M0 had to price before anything else started (from
docs/design/0.2.0-rust-rewrite.md §5, high). The plan also names scope creep as
a secondary risk, because "while we are in here" is how a rewrite becomes an
18-month project (from docs/design/0.2.0-rust-rewrite.md §5, high).

## What would reverse it

- A defect is found that the crate boundaries in §3 cannot hold without a cycle
  (inferred from docs/design/0.2.0-rust-rewrite.md §3, low).

## Consequences

- The Go tree (`cmd/`, `internal/`, `go.mod`, `go.sum`, `.golangci.yml`) is
  deleted at M9 (from docs/design/0.2.0-rust-rewrite.md §6, high).
- The workspace takes the `vlie` layout: `crates/` plus a thin root binary,
  dependencies pointing strictly downward (from
  docs/design/0.2.0-rust-rewrite.md §3, high).
- Anything outside the §2 defect list goes to 0.3.0 (from
  docs/design/0.2.0-rust-rewrite.md §5 and §8, high).

## How I will know it was realised

1. `cmd/` and `internal/` are absent and `crates/` holds the fourteen workspace
   crates; `ls crates` shows them (from crates/, high).
2. The engine holds no renderer: `crates/meowctl-engine/tests/running.rs` holds
   REQ-3051 and `SuspendOutput` appears only in doc comments (from
   crates/meowctl-engine/tests/running.rs and `rg SuspendOutput crates`, high).
3. Exit codes are chosen in one place: `tests/errors.rs` holds REQ-1031 (from
   tests/errors.rs, high).
4. `miette` is absent from every `Cargo.toml`, and a Starlark error renders
   with its span and caret: `crates/meowctl-starlark/tests/evaluation.rs` holds
   REQ-2240 (from `rg -l miette crates/*/Cargo.toml Cargo.toml` and that file,
   high).

## What this does not settle

- Which Starlark implementation runs underneath; ADR-0009 records that.
- What parity covers; ADR-0002 records that.
- The source recorded no alternative beyond a mechanical port, such as
  refactoring the Go tree in place (from docs/design/0.2.0-rust-rewrite.md §1,
  high).
